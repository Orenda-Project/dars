# Taleemabad — Company & Operations Context

## What Taleemabad does
Taleemabad is an edtech company that provides AI-powered teaching tools to schools in Pakistan. Core product is a curriculum-aligned lesson plan generator and related classroom tools.

## Who Dars serves

Dars has two audiences:
1. **Teachers directly** — via WhatsApp, the Dars web app, or direct access. This is the product vision; teacher value leads the story.
2. **FDS-style edtech teams** — integrate via the Dars API to deliver LPs to their own teachers at scale. These are the primary customers for Phase 1.

The webapp copy and product narrative lead with teacher value. FDS/API teams get their own dedicated section, not the headline.

## Client account model (evolving)

Currently a `Client` is just a name, API key, and optional webhook URL — created by an admin.

The direction is **self-serve client accounts**:
- Clients sign up with email + password from the webapp
- Client config stored on the account: default curriculum board, grade range, subjects, language preferences
- Foundation for: feature toggles, analytics dashboard, LP parameter defaults, billing (future)

## Teams relevant to Dars

### FDS (Forward Deployed Specialists) teams
- Go into regions (cities, districts) and work directly with teachers
- Goal: find product-market fit for Taleemabad tools in different contexts
- Often request lesson plans customized for their teachers — primary demand driver for Dars
- They are the **B2B clients** that Dars serves in Phase 1

### Core / Platform team
- Maintains `taleemabad-core` (Django monolith) — the main product
- Dars is a standalone service that borrows LP generation infrastructure from here

## The LP Generation Flow (Phase 1 goal)

This is the end-to-end flow Dars is building toward. Understanding it is critical.

### Concepts

**SLO (Student Learning Outcome)**
Issued by a government/curriculum authority (the SLO provider, e.g. NCP — National Curriculum of Pakistan). SLOs define what students should learn by the end of a topic. They are tied to a specific book, grade, and subject.

**Sub-SLO**
A granular breakdown of an SLO into specific, observable skills. e.g. SLO "reads with comprehension" → sub-SLO "identifies the main character in a story". Sub-SLOs are authored in the Schema tool and imported into Dars.

**Book → Chapter → Topic**
Books are physical textbooks used in classrooms, synced from taleemabad-core. Each book has chapters; each chapter has topics. Topics are the atomic units of teaching — one topic may take several lesson plans to cover.

**Topic ↔ Sub-SLO link**
Each topic is mapped to one or more sub-SLOs. This is what ties the book's content to the curriculum's learning objectives.

**Curriculum (a.k.a. Curriculum Breakdown)**
A named plan that binds together: a specific book + grade + subject + SLO provider + academic year. A book is provider-neutral; the curriculum is what pins it to a specific SLO set (NCP, SNC Punjab, etc.). The same book can have multiple curriculums for different providers or years.

**LP Stubs**
Within a curriculum, each topic is broken down into a sequence of lesson plan stubs by the LP Breakdown Module. A stub defines: what skill type this LP covers (reading, comprehension, revision, etc.), the CPA phase (concrete/pictorial/abstract), and Bloom's level. Stubs are the queue of LPs to be generated.

### End-to-end flow

```
SLO Provider (NCP, SNC, etc.)
    └── issues SLOs (per grade, subject, book)
         └── broken into Sub-SLOs (Schema tool → imported to Dars)

Book (synced from taleemabad-core)
    └── Book Chapters
         └── Topics
              └── linked to Sub-SLOs  ← the join that connects content to curriculum

Curriculum (named plan: book + grade + subject + provider + year)
    └── Curriculum Topics (ordered list of topics in this curriculum)
         └── LP Stubs (breakdown module decides: 2× reading, 1× comprehension, 1× revision)
              └── Lesson Plan (generated by LP Assistant, stored in Dars)
```

### LP Breakdown Module
An AI step that takes a curriculum topic (with its sub-SLOs and topic text) and decides how many lesson plans to generate and what kind. Example output for "The Giving Tree" topic:
- LP 1: reading, concrete, remember
- LP 2: reading, pictorial, understand
- LP 3: comprehension, abstract, apply
- LP 4: revision

This produces the LP stubs. Once stubs exist, generation can be triggered individually or in bulk.

### LP Generation from Topic Text (planned LP Assistant change)
Currently the LP Assistant generates LPs from page numbers — it fetches OCR text for those pages. The plan is to update this so Dars can pass topic text directly, bypassing the page/OCR dependency. This requires a change to the LP Assistant pipeline.

## LP Assistant service

- Lives at `lp-assistant.taleemabad.com`
- Codebase: `/home/hataf/taleemabad/UG_LessonPlan/`
- Generates HTML lesson plans from curriculum metadata
- Auth: `api-key` header (hardcoded shared secret)

### Key endpoints

| Endpoint | What it does |
|---|---|
| `POST /api/generate-lp` | Synchronous LP generation (~60s) |
| `POST /api/generate-lp-webhook` | Async LP generation with callback URL |
| `GET /api/webhook-status/{job_id}` | Poll async job status |
| `POST /api/edit-lp` | Edit an existing LP HTML given instructions |

### Current generate-LP request (page-based)
```json
{
  "curriculum": "ICT",
  "grade": 3,
  "subject": "Maths",
  "page_number": "10",
  "class_strength": 30,
  "exercise_page_number": "",
  "custom_prompt": "",
  "generate_bilingual": false,
  "reasoning_enabled": true
}
```

### Planned generate-LP request (topic text-based)
The LP Assistant pipeline needs to accept topic text directly instead of page numbers:
```json
{
  "curriculum": "ICT",
  "grade": 3,
  "subject": "English",
  "topic_title": "Characters and Setting",
  "topic_text": "...",
  "sub_slos": ["Identifies the main character in a story", "..."],
  "skill_type": "reading",
  "cpa_phase": "concrete",
  "blooms_level": "understand",
  "class_strength": 30,
  "generate_bilingual": false,
  "reasoning_enabled": true
}
```
This is a required change in `UG_LessonPlan/` before Dars can generate LPs from curriculum topics.

- **ICT** — Islamabad Capital Territory (national/federal curriculum)
- **NCP** — National Curriculum of Pakistan (SLO provider, cross-board)

## Vocabulary

- **LP** — Lesson Plan
- **SLO** — Student Learning Outcome (issued by curriculum authority, tied to a book)
- **Sub-SLO** — Granular breakdown of an SLO into observable skills
- **Topic** — Atomic teaching unit within a book chapter; mapped to sub-SLOs
- **Curriculum** — Named plan binding book + grade + subject + SLO provider + year
- **LP Stub** — Pre-defined slot for an LP within a curriculum (skill type, CPA phase, Bloom's level)
- **LP Breakdown Module** — AI step that decides how many and what kinds of LPs a topic needs
- **FDS** — Forward Deployed Specialists (regional B2B clients)
- **ICT / Punjab / Sindh / AKU-EB** — curriculum/board types
- **NCP** — National Curriculum of Pakistan (SLO provider)
- **Bilingual** — English + Urdu version of the lesson plan
- **CPA** — Concrete / Pictorial / Abstract (pedagogical phases)
- **Bloom's** — Bloom's Taxonomy levels (remember, understand, apply, analyze, evaluate, create)
