# Glossary — Chapter Planning Engine

Future docs may only use terms defined here. Add a term when it first appears.

| Term | Definition |
|------|------------|
| **Chapter Planning Engine (CPE)** | The standalone service this feature builds. Standalone FastAPI app under `dars/chapter-planner-app/`. |
| **Chapter** | The unit of input. A named section of a book containing one or more **Topics**, taught over a given **Period count**. |
| **Topic** | A teachable sub-section of a Chapter (e.g. "Greetings", "Letters A–E"). Carries `topic_text` (the source/page content) and a set of **SLOs**. |
| **SLO** | Student Learning Outcome — a single intended learning result (e.g. "Student should use Adverbs of Time"). Attached to Topics. The plan must ensure every chapter SLO is covered by ≥1 unit. |
| **Period count** | Number of teaching periods/units available for the Chapter. Drives how many **Plan Units** the plan contains (3 periods → roughly 3 units). |
| **Chapter Plan** | The output. An ordered list of **Plan Units** that together cover all chapter SLOs in the given Period count. |
| **Plan Unit** | One ordered item in a Chapter Plan = the spec for one downstream LP. Carries: `sequence`, `lp_type`, `topic_ids` (≥1), `slo_ids` (≥1), `topic_text` (resolved), and a short `rationale`. Not the LP itself. |
| **LP (Lesson Plan)** | The downstream artifact generated by `UG_LessonPlan` from a Plan Unit. Out of scope for CPE — CPE only plans which LPs to make. |
| **lp_type** | The skill-type of an LP, constrained per subject by `VALID_LP_TYPES` (see [06-reference-ug-lp-input.md](06-reference-ug-lp-input.md)). The LLM chooses it per Plan Unit. e.g. Eng: `reading`, `grammar`, `comprehension_qa`, …; Maths: `concrete`, `word_problems`, … |
| **FA (Formative Assessment)** | Out of scope for v2 (assessments ignored per user). CPE emits only LP Plan Units this round. |
| **PlanValidator** | Pure function that checks an LLM plan against hard invariants (unit count vs period count, SLO coverage, valid lp_type) before the plan is trusted. |
| **PlannerLLM** | The interface CPE calls to reach Claude. v2 uses the **Agents-SDK backend** (OAuth, dev). |
| **Agents-SDK backend** | `claude-agent-sdk` running against the developer's Claude Code OAuth session. Used for local iteration — no console API spend. Not a production credential. |
| **Iteration harness** | The eval/test rig (Phase 3) that runs sample Chapters through the planner and lets the user + Claude judge plan quality and iterate the prompt. |
| **Dars planner (deterministic)** | The existing `make_chapter_plan` flow in the dars backend (`intelligent-chapter-planner` feature) that CPE will eventually replace. Out of scope to modify in v2. |
