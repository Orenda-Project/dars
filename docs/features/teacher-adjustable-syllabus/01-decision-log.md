# Decision Log — Teacher-Adjustable Syllabus (suggestion-led)

Frozen architectural decisions. To revise: ask the user, mark old "Superseded by D-N+1 on YYYY-MM-DD", add new referencing the supersession. Both stay.

---

**D-1: The global syllabus is advisory; the class owns its own teaching path. Do NOT reintroduce per-class syllabus scope.** *Rationale:* an earlier draft of this plan forked the global into an editable class-scoped syllabus. The user reframed: the global should only *suggest*; the class records its own real path. So no `scope`/`cst_id` on `syllabus_breakdowns`, no fork-on-edit of a full syllabus. *Apply:* the class path lives in a new `class_chapters` table (D-2); the global stays global + unchanged. *Decided:* 2026-06-03. *Supersedes:* the fork-on-edit approach explored earlier this session (never built).

**D-2: The class's teaching path is a new per-CST table `class_chapters`. Picking a chapter records a row; it does not generate slots.** *Rationale:* the teacher chooses which chapters to teach, in what order, with dates — that choice is first-class state, separate from breaking a chapter down. *Apply:* `class_chapters(id, cst_id, book_chapter_id, position, start_date, end_date, …)`. "Pick a chapter" inserts a row (Action 1). "Break it down" (Action 2) is separate. *Decided:* 2026-06-03 (user: "just records the choice; break down separately").

**D-3: The global default supplies a *recommendation* for the next chapter; the teacher may pick it or any other chapter.** *Rationale:* suggestion-led. At session start (empty path), the app says "nothing planned — the default suggests Chapter 1; what would you like to teach?" with Ch 1 recommended and all chapters selectable. *Apply:* a "recommended next" derivation from the global's order vs. what's already in the class path. *Decided:* 2026-06-03.

**D-4: Chapter status (yet-to-start / in-progress / done) is derived from the chapter's generated class slots.** *Rationale:* status reflects real teaching, not a separate flag to keep in sync. Per chapter (by `book_chapter_id` for the CST): **done** = all its slots terminal (taught/completed/skipped), **in-progress** = some terminal, **yet-to-start** = a path row with no terminal slots (incl. not-yet-broken-down). *Apply:* derived on read in the syllabus/path endpoint. *Decided:* 2026-06-03. *Note:* "done" needs the chapter to have been broken down; a picked-but-unbroken chapter is yet-to-start.

**D-5: "Break it down" (Action 2) reuses the shipped `generate_chapter_plan` unchanged, keyed off a chapter in the class path.** *Rationale:* the period-count → planner → class-slots → show-LPs flow already works (shipped in `syllabus-breakdown-and-teacher-chapter-plan`). Period count = real teaching periods in the chapter's date range (`compute_teaching_days`). *Apply:* break-it-down operates on a `class_chapters` chapter (with the dates from its path row). No new generation logic. *Decided:* 2026-06-03 (user: "reuse existing break-it-down").

**D-6: Reorder is allowed for upcoming (yet-to-start) chapters only; in-progress/done chapters are locked.** *Rationale:* the past is immutable — a chapter with taught history can't be moved or removed; future chapters are freely reorderable. This is what dissolves the half-taught-chapter problem: a partially-taught chapter is just `in-progress` and stays put. *Apply:* reorder/remove endpoints reject changes to non-yet-to-start chapters. *Decided:* 2026-06-03 (user: "order = pick order + can reorder upcoming; lock the taught").

**D-7: Chapters enter the class path UNDATED; the teacher sets each chapter's date range.** *Rationale:* user chose teacher-set dates over copy-from-global. Break-it-down needs a date range (it 422s without one), so the teacher dates a chapter before/at break-down. *Apply:* `class_chapters.start_date/end_date` nullable, set by the teacher. *Decided:* 2026-06-03.

**D-8: Assessments are dropped — break-it-down generates lesson plans only (no formative/summative).** *Rationale:* simplify the LLM/generation model (user request). A chapter's periods all become LPs (lessons + the planner's revision LP, which is also a lesson-table slot). No `class_assessment_slots` rows generated. *Apply:* see D-9 for scope. *Decided:* 2026-06-03. *Open until confirmed:* scope of removal (D-9).
