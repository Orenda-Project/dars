# Decision log — LP Showcase Multi-Grade

Frozen. To revise: mark old "Superseded by D-N+1 on YYYY-MM-DD"; new references the supersession. Both stay.

---

**D-1: Sidebar layout — add a third group labelled "Multi-Grade".** *Rationale:* User picked this over duplicating entries under every grade in the span (would muddle navigation) and over a banner row above the sidebar (visually inconsistent). A new group keeps the existing grade-as-primary mental model intact while making multi-grade discoverable. *Apply:* `webapp/components/templates/showcase-template.tsx` — extend `grouped` to bucket multi-grade entries into a `"Multi-Grade"` group, rendered after the numeric grade groups. *Decided:* 2026-05-21.

**D-2: Seed scope — 2–3 multi-grade LPs.** *Rationale:* User asked for "2-3 multi grade lps" — enough to demonstrate the capability without spending on a full 10-LP matrix. Concrete picks: a G2–G3 Reading LP, a G4–G5 Comprehension Q&A LP, and (if budget allows in one run) a G1–G5 full-span Creative Writing LP. *Apply:* `useful-scripts/generate_showcase_lps.py` SPECS list. *Decided:* 2026-05-21.

**D-3: Use LP Assistant `/api/v1/generate-lp-multigrade` as-is.** *Rationale:* Verified against `UG_LessonPlan` `main@4ec7b1d` (latest at decision time): the endpoint accepts the shape we need (`grades: List[int]`, `per_grade_page_numbers: Dict[str, str]`, etc., 2–5 grades, subjects Eng/Maths/Urdu, page numbers OR raw content). Endpoint is webhook-only (callback_url required, 202 Accepted + job_id) — same Redis-backed job model as the existing single-grade webhook path. *Apply:* generator script gets a new `generate_one_multigrade()` code path that POSTs to the multigrade endpoint and polls `/api/webhook-status/{job_id}` until terminal status. The polled response shape nests the lesson plan under `data.response.lesson_plan` (RedisCache convention) — not directly on `data`. See [04-reference-lp-assistant-multigrade.md](04-reference-lp-assistant-multigrade.md) for the full contract. *Decided:* 2026-05-21.

**D-4: Polling, not callbacks.** *Rationale:* The existing showcase generator is a one-shot CLI run from a developer machine. Standing up a callback server for a 90-second async job is over-engineered; LP Assistant exposes `GET /api/webhook-status/{job_id}` for exactly this case. Use a placeholder `callback_url` (e.g. `https://lp-assistant.taleemabad.com/api/webhook-status/<placeholder>`) which is a known no-op POST sink, then poll for completion. *Apply:* generator script — pass a placeholder callback_url, poll every 5s with a 5-minute ceiling. *Decided:* 2026-05-21.

**D-5: No AI review for multi-grade LPs.** *Rationale:* User stated "there is no multi grade ai reviewer so you can skip that." The `/api/review-lp` endpoint is single-grade only and `review_one()` posts a single `grade: int`. Multi-grade entries must record `review_status: "MISSING"` (with a one-line `review_error` explaining "no multi-grade reviewer") so the existing `ReviewDrawer` null-render path takes over — no review UI rendered for these entries. *Apply:* `generate_showcase_lps.py` `write_results()` — multi-grade entries get `review_status: "MISSING"`, `review_error: "no multi-grade reviewer available"`. `run_reviews()` — skip entries whose `grade` is a list. *Decided:* 2026-05-21.

**D-6: Data shape — `grade` becomes `number | number[]` in `index.json`.** *Rationale:* Most existing entries are `grade: 2` / `grade: 5`; multi-grade entries need to carry the full grade set. Widening the field is cleaner than adding a parallel `grades: number[]` field and harmonises with LP Assistant's input shape (`grades: List[int]`). Frontend grouping logic discriminates on `Array.isArray(grade)`. Sidebar group label for arrays: "Multi-Grade · G{min}–G{max}" or "Multi-Grade · G1, G3, G5" if non-contiguous. *Apply:* `showcase-template.tsx` `ShowcaseEntry` type + grouping + header label. `generate_showcase_lps.py` `LPSpec.grade` becomes `int | list[int]`. *Decided:* 2026-05-21.

**D-7: Multigrade endpoint returns structured JSON, not HTML — render in Python in the generator.** *Rationale:* Discovered during F-1.5 execution: the single-grade `/api/generate-lp` endpoint returns `lesson_plan: "<html string>"`, but the multigrade `/api/v1/generate-lp-multigrade` endpoint returns `lesson_plan` as a parsed JSON dict (`title`, `slo_progression`, `combined_opening`, `board_prep`, `rotations[]`, `combined_closing`, `peer_tutoring_setup`). LP Assistant's own UI renders this JSON client-side in `UG_LessonPlan/static/index.html:2014+` (function `displayMultigradeLessonPlan`). The showcase needs static HTML files, so we port the renderer to Python inside the generator script. The renderer outputs Dars-styled HTML using the same `<body class="lp-doc">` shell + `/showcase/_assets/lp.css` stylesheet as single-grade entries, so the iframe rendering path needs no changes. **D-3 still stands** (use the endpoint as-is); this is purely about how the response is converted to display HTML. *Apply:* new `render_multigrade_html()` function in `generate_showcase_lps.py`; `generate_one_multigrade()` passes the dict through it before returning `LPResult.html`. *Decided:* 2026-05-21 (mid-execution).
