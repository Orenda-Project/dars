# Decision Log — Teacher Read-Only Syllabus

Frozen. To revise: ask the user, mark the old "Superseded by D-N on YYYY-MM-DD", add the new. Both stay.

---

**D-1: The org's published Syllabus Breakdown is the single source of truth for the teacher's path.** *Rationale:* User wants teachers to teach the org-decided curriculum, not their own. Which chapters, in what order, on what dates — all come from `syllabus_chapters` of the published breakdown for the CST's (curriculum, grade, subject) triple. The teacher cannot modify any of it. *Apply:* Phases 1 + 2. *Decided:* 2026-06-09 (user).

**D-2: The teacher path (`class_chapters`) is auto-seeded from the published breakdown, then read-only.** *Rationale:* User chose "auto-seed all chapters on first view." Break-it-down and the slot tables key off `class_chapters`, so the path must still physically exist there — but it's now a copy of the org breakdown, not teacher input. On the first syllabus read for a CST (and idempotently thereafter), copy every published-breakdown chapter into `class_chapters` (book_chapter_id, position, start_date, end_date) that isn't already present. *Apply:* Phase 1 — a `seed_class_chapters_from_breakdown(conn, cst_id)` helper invoked by the syllabus GET. *Decided:* 2026-06-09 (user). *Note:* idempotent + safe against the `UNIQUE (cst_id, book_chapter_id)` / `UNIQUE (cst_id, position)` constraints; skip rows already present (a partially-built legacy path is left as-is but completed from the breakdown).

**D-3: Period count stays derived from the CST timetable — no teacher-entered number.** *Rationale:* User clarified the periods come from the teacher *because they maintain their own timetable*; the timetable tells us the periods. So "based on their number of periods" = the existing `chapter_slot_count` (teaching days in the chapter's date range on the CST timetable weekdays, minus holidays). No new period-count input; break-it-down is unchanged. *Apply:* nothing to build — confirm generate-chapter-plan still derives count this way. *Decided:* 2026-06-09 (user).

**D-4: Delete the 4 teacher mutation endpoints, their service functions, webapp controls, and API-client functions.** *Rationale:* User chose "remove UI and delete the endpoints." The path is no longer teacher-editable, so pick / set-dates / reorder / remove have no caller. Remove: `pick_class_chapter` (`POST …/chapters`), `set_class_chapter_dates` (`PATCH …/chapters/{id}`), `reorder_class_chapters` (`PUT …/chapters/order`), `remove_class_chapter` (`DELETE …/chapters/{id}`) in `router_class_actions.py`; the matching service functions `pick_chapter`, `reorder_*`, `remove_*`, date-set in `class_chapter_service.py`; the `slots.pickChapter/setChapterDates/reorderChapters/removeChapter` functions in `webapp/lib/dars-api.ts`; and all four controls in the syllabus tab. *Apply:* Phase 1 (backend) + Phase 2 (frontend). *Decided:* 2026-06-09 (user). *Note:* `test_class_chapter_service.py` exercises pick/reorder/remove — those tests are removed/rewritten for the auto-seed model (D-2) in Phase 1. Onboarding does NOT use these (it writes `cst_state`, not `class_chapters`) — safe.

**D-5: Drop `recommended_next` from the teacher syllabus response/UI.** *Rationale:* Once the whole path is auto-seeded (D-2), the teacher already has every org chapter — there is no "next to pick." The `recommended_next` field and the `recommended_next_chapter()` call become dead for the teacher view. Remove it from the syllabus GET response shape and the UI. *Apply:* Phase 1 (response) + Phase 2 (UI). *Decided:* 2026-06-09. *Note:* keep `recommended_next_chapter()` the function only if something else uses it; grep showed only the syllabus GT — if so, remove it too.

**D-6: No schema change, no migration.** *Rationale:* `class_chapters` already has `book_chapter_id`, `position`, `start_date`, `end_date`; `syllabus_chapters` already has the same. Auto-seed is a copy between existing tables. *Apply:* whole feature. If a migration seems needed, STOP — it contradicts this. *Decided:* 2026-06-09.

**D-7: No date range / no published breakdown → read-only empty state, not an editable fallback.** *Rationale:* If the CST has no published Syllabus Breakdown (none exists for its triple), the teacher sees an empty, read-only "your org hasn't published a syllabus yet" state — NOT the old chapter picker. The teacher never gets an editing affordance. A chapter whose org dates yield 0 teaching days still shows but its Generate action is disabled with a clear reason (as today). *Apply:* Phase 1 response + Phase 2 UI. *Decided:* 2026-06-09.
