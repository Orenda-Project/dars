# Curriculum LP Pipeline — Implementation Plan

## Goal

Build the full pipeline from "here is a book" to "here is a complete, dated schedule of lesson plans for the year." Teachers get a default curriculum generated by admin, can clone and customize it, and can track whether they are ahead or behind.

---

## End State (what you can do when this is done)

**Admin can:**
- Sync a book from taleemabad-core
- Run the breakdown pipeline: provide book + date range + days/week → system generates a fully scheduled curriculum with dated LP stubs
- Publish the curriculum as the default for that book+provider

**Teacher can:**
- See the default curriculum for their book — ordered topics, planned dates, LP stubs per topic
- Clone it and adjust topic sequence and dates to their preference
- Mark a topic as completed (sets completed_date)
- See their progress: ahead / on track / behind
- Trigger LP generation for any stub → get a real lesson plan

**What is NOT in scope here:**
- Webapp UI for any of this (API only)
- Sub-SLO import from Schema tool (data seeded via script for now)
- LP Assistant topic-text mode (separate work in UG_LessonPlan — tracked separately)

### Phase 1 — Real curriculum read API
**Bead:** bd-018

Replace all mock/hardcoded endpoints with real DB queries. No AI, no generation — just reading what's in the DB.

**Endpoints:**

| Method | Path | What it returns |
|--------|------|----------------|
| GET | `/api/v1/books` | Books list with filters (board, grade, subject) |
| GET | `/api/v1/books/{id}` | Book detail + chapters + topics (with sub-SLOs) |
| GET | `/api/v1/curriculums` | Active curriculums (default + teacher's own) |
| GET | `/api/v1/curriculums/{id}` | Curriculum detail: ordered topics → LP stubs (with planned_date, status) |
| GET | `/api/v1/curriculums/{id}/progress` | Ahead/behind summary: total topics, completed, behind, ahead |

**Auth:** all require `X-API-Key`. Curriculum list returns admin defaults + teacher's own (filtered by `client_id`).

**Outcome:** A client can browse books, see topics, and read a full curriculum schedule.

### Phase 2 — Curriculum admin CRUD
**Bead:** bd-019

Endpoints for admin to create and manage default curriculums. Manual creation (not AI — that's Phase 4).

**Endpoints:**

| Method | Path | What it does |
|--------|------|-------------|
| POST | `/api/admin/curriculums` | Create a curriculum (book_id, provider_id, name, is_default) |
| POST | `/api/admin/curriculums/{id}/topics` | Set the ordered topic list for a curriculum (array of topic_ids + planned_dates) |
| PATCH | `/api/admin/curriculums/{id}` | Update name, is_default, is_active |
| DELETE | `/api/admin/curriculums/{id}/topics/{topic_id}` | Remove a topic from curriculum |

**Outcome:** Admin can manually assemble a curriculum and assign dates to topics.

---

### Phase 3 — Teacher curriculum clone + progress tracking
**Bead:** bd-020

Teachers can clone a default curriculum, reorder topics, adjust dates, and mark topics as done.

**Endpoints:**

| Method | Path | What it does |
|--------|------|-------------|
| POST | `/api/v1/curriculums/{id}/clone` | Clone a curriculum (default or own) → new curriculum with `teacher_id` set |
| PATCH | `/api/v1/curriculums/{id}/topics/{topic_id}` | Update `planned_date`, `sequence` on a curriculum topic |
| POST | `/api/v1/curriculums/{id}/topics/{topic_id}/complete` | Set `completed_date = today` |
| DELETE | `/api/v1/curriculums/{id}/topics/{topic_id}` | Remove topic from teacher's curriculum |

**Rules:**
- Teachers can only modify their own curriculum (`teacher_id` must match)
- Cannot modify admin default (`is_default=true`) — must clone first
- Clone copies all `curriculum_topics` + `curriculum_lp_stubs` including `planned_date`

**Outcome:** Teachers have a personal curriculum they can customize. Progress tracking works.

---

### Phase 4 — AI breakdown pipeline
**Bead:** bd-021

The AI step that takes a book + date range and produces a fully scheduled curriculum.

**Two sub-steps:**

**Step A — Chapter planner**
- Input: `book_id`, `start_date`, `end_date`, `days_per_week`
- Logic: fetch chapters, compute total teaching days available, distribute days across chapters proportional to chapter length/complexity (LLM call)
- Output: `{ chapter_id: days_allocated }` map

**Step B — Topic/LP planner** (runs per chapter)
- Input: chapter + `days_allocated` + sub-SLOs per topic
- Logic: order topics, decide how many LPs per topic and what kind (reading/comprehension/revision etc.), assign one LP per day, assign dates
- Output: `curriculum_topics` rows + `curriculum_lp_stubs` rows with `planned_date`

**Endpoint:**
```
POST /api/admin/curriculums/generate
{
  "book_id": "...",
  "provider_id": "...",
  "name": "Grade 3 English NCP 2025-26",
  "start_date": "2025-09-01",
  "end_date": "2026-06-30",
  "days_per_week": 5,
  "is_default": true
}
```

Response: the created `Curriculum` with all topics and stubs.

**Outcome:** Admin provides a book + date range → full curriculum schedule created in one shot.

---

### Phase 5 — LP generation from stubs
**Bead:** bd-022

Generate actual lesson plans from LP stubs. Each stub → one LP.

**Endpoints:**

| Method | Path | What it does |
|--------|------|-------------|
| POST | `/api/v1/curriculums/{id}/stubs/{stub_id}/generate` | Generate LP for one stub (async, 202) |
| POST | `/api/v1/curriculums/{id}/generate-all` | Queue generation for all pending stubs (background) |
| GET | `/api/v1/curriculums/{id}/stubs/{stub_id}` | Get stub status + lesson_plan_id when done |

**LP Assistant call:** uses current page-based API with topic text + sub-SLOs injected into `custom_prompt`. Proper `topic_text` mode (in UG_LessonPlan) is a separate dependency tracked outside this plan.

**Stub status flow:** `pending → generating → generated / failed`

On success: `stub.lesson_plan_id` is set, `stub.status = generated`.
On failure: `stub.status = failed`, retry available via the single-stub endpoint.

**Outcome:** A full curriculum can have all its LPs generated. Teacher can click into any stub and read the LP.

## Build order

```
Phase 0 (schema) → Phase 1 (read API) → Phase 2 (admin CRUD)
                                      → Phase 3 (teacher clone)
                                      → Phase 4 (AI breakdown)  ← depends on Phase 2
                                      → Phase 5 (LP generation) ← depends on Phase 1
```

Phases 1–3 and 5 are mostly independent after Phase 0. Phase 4 depends on Phase 2 (needs curriculum CRUD before generating one).
